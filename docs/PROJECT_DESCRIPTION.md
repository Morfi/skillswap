# SkillSwap — описание проекта

## 1. Идея и проблема

Почти каждый человек что-то умеет хорошо и при этом хочет научиться чему-то новому. Студент свободно говорит по-английски, но мечтает играть на гитаре; программист хочет научиться готовить; повар — разобраться в Python. Классические пути — платные курсы и репетиторы — стоят дорого, а бесплатные видеоуроки не дают живой обратной связи и мотивации.

При этом рядом всегда есть люди, у которых «зеркальная» ситуация: они умеют то, что нужно вам, и хотят научиться тому, что умеете вы. Проблема в том, что найти такого человека практически невозможно: объявления разбросаны по чатам и форумам, нет поиска по навыкам, нет механизма договориться и нет способа понять, можно ли доверять партнёру.

**SkillSwap** — веб-платформа для бартера знаний: «научу тому, что умею, — научусь тому, что хочу». Деньги в системе не участвуют вообще: единственная «валюта» — это время и навыки самих пользователей.

## 2. Цель и ценность

**Цель проекта** — сделать обучение доступным, соединяя людей, которые могут взаимно научить друг друга.

Ценность для пользователя:

- **Бесплатное обучение** с живым человеком вместо дорогих курсов.
- **Автоматический подбор партнёров** — не нужно вручную перебирать объявления: система сама находит людей, с которыми возможен взаимовыгодный обмен.
- **Прозрачный процесс** — заявка, принятие, проведение занятий, завершение и взаимная оценка.
- **Доверие** — рейтинг пользователя формируется только по реально завершённым обменам.
- **Новые знакомства** — фильтр по городу и формату (онлайн/офлайн) помогает найти людей рядом.

## 3. Уникальность

В отличие от досок объявлений и маркетплейсов репетиторов, SkillSwap строится вокруг **взаимности**. Каждый пользователь описывает две стороны себя:

- **«Научу» (offer)** — навыки, которыми он готов поделиться;
- **«Хочу научиться» (want)** — навыки, которые он ищет.

Алгоритм подбора сопоставляет «хочу» одного пользователя с «научу» другого **в обе стороны**. Если совпадение двустороннее, оно помечается как 🤝 **«Взаимный обмен»** и поднимается в начало выдачи. Совпадение оценивается по названию навыка (полное вхождение или общие значимые слова) и по категории, а при равных баллах выше показываются партнёры с лучшим рейтингом.

## 4. Целевая аудитория

| Сегмент | Пример | Что получает |
|---|---|---|
| Студенты | Знает английский, хочет программирование | Бесплатное обучение и практику преподавания |
| Молодые специалисты | IT-специалист хочет освоить музыку или спорт | Хобби без больших затрат |
| Люди с хобби | Повар, тренер по йоге, художник | Возможность поделиться опытом и получить новый навык |
| Переехавшие в новый город | Ищет знакомства | Живое общение по интересам |
| Администраторы сообщества | Модерация платформы | Инструменты управления пользователями и контентом |

## 5. Роли пользователей

**Гость** — видит страницу входа и регистрации.

**Пользователь (user)**:
- регистрируется, входит в систему, редактирует профиль (имя, город, о себе);
- создаёт, просматривает, редактирует и удаляет **свои навыки** (offer/want);
- ищет навыки в каталоге с фильтрами (тип, категория, уровень, формат, город, текст);
- получает список подобранных партнёров;
- отправляет, редактирует, отменяет и удаляет **заявки на обмен**; принимает или отклоняет входящие;
- завершает обмен и ставит оценку партнёру от 1 до 5;
- смотрит публичные профили других людей с их рейтингом.

**Администратор (admin)** — всё, что может пользователь, плюс:
- видит статистику платформы (пользователи, навыки, обмены по статусам, навыки по категориям);
- управляет пользователями: меняет роль, блокирует/разблокирует, удаляет;
- модерирует контент: удаляет любые навыки и любые заявки на обмен;
- просматривает заявки всех пользователей.

## 6. Бизнес-сущности

### 6.1 Навык (Skill) — CRUD №1

| Поле | Описание |
|---|---|
| `kind` | `offer` — «научу», `want` — «хочу научиться» |
| `title` | Название навыка |
| `category` | languages, music, it, sport, art, cooking, science, crafts, business, other |
| `level` | beginner / intermediate / expert |
| `format` | online / offline / both |
| `description` | Подробности |
| `is_active` | Показывать ли в каталоге |
| `owner_id` | Владелец |

Правила: редактировать и удалять навык может только владелец или администратор. Скрытые (`is_active = false`) навыки и навыки заблокированных пользователей не видны в каталоге и подборе.

### 6.2 Заявка на обмен (Exchange) — CRUD №2

| Поле | Описание |
|---|---|
| `requester_id` | Кто отправил заявку |
| `receiver_id` | Владелец запрошенного навыка |
| `requested_skill_id` | Навык, которому хотят научиться (offer получателя) |
| `offered_skill_id` | Что предлагают взамен (offer отправителя, необязательно) |
| `message` | Сопроводительное сообщение |
| `status` | pending → accepted / declined / cancelled; accepted → completed / cancelled |
| `requester_rating`, `receiver_rating` | Оценки, поставленные участниками после завершения |

Жизненный цикл заявки:

```
           ┌── accepted ──┬── completed ──► оценки 1–5
pending ───┤              └── cancelled
           ├── declined   (решает получатель)
           └── cancelled  (решает отправитель)
```

Правила: нельзя запросить собственный навык; нельзя иметь две активные заявки на один и тот же навык; редактировать заявку может только отправитель и только пока она в статусе `pending`; удалить — отправитель (если заявка не принята) или администратор; оценить — каждый участник один раз и только завершённый обмен.

### 6.3 Пользователь (User)

Email (уникальный), имя, город, «о себе», хэш пароля (bcrypt), роль (`user`/`admin`), флаг блокировки.

## 7. Архитектура

```
┌──────────────┐   HTTP :8080   ┌───────────────────┐  /api/*  ┌──────────────────┐  SQL  ┌──────────────┐
│   Браузер    │ ─────────────► │ frontend (nginx)  │ ───────► │ backend (FastAPI)│ ────► │ db (Postgres)│
└──────────────┘                │ статический SPA   │          │ JWT, бизнес-логика│       │   volume     │
                                └───────────────────┘          └──────────────────┘       └──────────────┘
```

Все три компонента запускаются в отдельных Docker-контейнерах через `docker compose`:

- **db** — PostgreSQL 16, данные хранятся в именованном volume, есть healthcheck;
- **backend** — Python 3.12, FastAPI, SQLAlchemy 2.0, Pydantic v2; при старте создаёт таблицы, администратора и демо-данные; документация API Swagger — `/api/docs`;
- **frontend** — nginx раздаёт одностраничное приложение на чистом JavaScript (без сборки) и проксирует `/api` на backend, поэтому нет проблем с CORS.

### Авторизация

- Пароли хранятся только в виде bcrypt-хэшей.
- При входе/регистрации выдаётся JWT (HS256) со сроком жизни 24 часа, в нём `sub` (id пользователя) и `role`.
- Каждый защищённый запрос проверяет токен (`Authorization: Bearer …`) и подгружает пользователя из БД — поэтому смена роли и блокировка вступают в силу сразу.
- Административные эндпоинты (`/api/admin/*`) защищены зависимостью `require_admin` (403 для обычного пользователя).
- Первый администратор создаётся автоматически из переменных окружения `ADMIN_EMAIL` / `ADMIN_PASSWORD`.

## 9. MVP и развитие

**MVP** (реализован) покрывает 20 ключевых сценариев, отмеченных в [USE_CASES.md](USE_CASES.md): регистрация и вход, роли, CRUD навыков, каталог с поиском, подбор партнёров, полный жизненный цикл заявки на обмен и базовое администрирование.

**Дальнейшее развитие** (остальные use cases): встроенный чат между участниками обмена, календарь занятий и напоминания, отзывы с текстом, загрузка аватаров, уведомления по email/Telegram, геопоиск на карте, групповые обмены «по кругу» (A учит B, B учит C, C учит A), достижения и бейджи, жалобы и модерация отзывов, мобильное приложение.

## 10. Метрики успеха

- количество взаимных совпадений на одного пользователя;
- конверсия «заявка → принята → завершена»;
- средний рейтинг партнёров и доля обменов с оценкой;
- доля пользователей, у которых есть и «научу», и «хочу научиться»;
- число повторных обменов (retention).
